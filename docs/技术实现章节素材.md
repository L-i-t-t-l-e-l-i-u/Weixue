## 1. 总体架构

系统采用前后端分离 + **双模式**设计，同一套 UI 在两种形态下运行：

- **纯前端演示模式**（`VITE_DEMO_MODE` 构建期开关）：无后端依赖，`demoClient.js`
  在浏览器内用内存数据模拟全部接口，静态托管于 GitHub Pages，评委点开即用；
- **完整模式**：React 18 + Vite + Zustand + Tailwind 前端，经 `/api` 代理连接
  FastAPI + SQLAlchemy + SQLite 后端，真实调用大模型与语音识别服务。

技术选型理由：比赛演示要"零安装可体验"（演示模式），又要经得起真实链路检验
（完整模式），双模式用同一套页面组件与接口契约覆盖两种需求，切换仅取决于构建参数。

## 2. 「AI 准备，教师决定」的技术落地

大赛红线是 AI 只做脚手架、决定权在教师。代码层面的对应设计：

- AI 评估输出三态置信度 `certain_good / certain_weak / uncertain`，
  **不确定就明说不确定**：评估异常、文本为空、模型返回矛盾结果时一律归一为
  `uncertain` 且不残留分数，前端显示"待评估"，绝不冒充已评；
- 所有 AI 产物（维度分数、评语草稿、建议标签）都是**可逐条修改、可整体重置**的
  "建议"：教师批改接口覆盖 AI 结果并记录校准差异，`reset` 一键清空重来；
- 批量评估失败不阻塞、不静默：失败条目保留可重试状态（`submitted`），
  进度接口实时暴露成功/失败/跳过计数，教师随时知道哪些没评成；
- 口述作答以转写文本进入评估，原始音频留档可回溯（`AudioRecording` 表）。

## 3. 语音转写管线（可插拔 ASR 层）

`backend/asr.py` 抽象四个 provider，环境变量或运行期 API（`GET/POST /api/settings/asr`）
切换并持久化：

| provider | 用途 | 状态 |
|---|---|---|
| `mock` | 离线演示保底，写入内置演示文本 | 已验证 |
| `qwen_asr` | **推荐**：百炼 qwen3-asr-flash，chat/completions + base64 音频直传，免公网 URL | 已验证：探测 + 8/11 真实 45s 音频端到端实测通过 |
| `openai` | whisper 兼容端点 | 接口已实现（百炼 compatible-mode 实测无此端点） |
| `dashscope` | paraformer SDK 本地文件路线 | 接口已实现，备选 |

配套：

- `backend/audio_utils.py` 音频预处理：m4a/webm/ogg/mp4 → 16k 单声道 WAV
  （qwen_asr/paraformer 标准输入），缺 ffmpeg 给出分平台安装提示；
  附 45 秒示例课堂音频；
- 上传失败分级兜底：客户端预检（格式白名单、大小上限）+ 后端失败全清理
  （不留临时文件与残行）+ 前端按错误码给可操作文案，始终保留"粘贴转写文本"人工通道；
- 切换真实模式自动清除演示种子数据、切回 mock 自动补种——演示与真实数据互不污染。

## 4. 评估管线

- 三维度（清晰性 / 解释力 / 证据意识）× 认知梯度评分量规，按学生认知层级
  组装 system prompt，近 10 条教师校准记录注入上下文（教师批改越多，AI 越贴近该教师尺度）；
- 批量评估为后台任务：`POST /assess` 启动 → 前端 500ms 轮询进度 →
  完成/失败实时可见；检查与占位在同一锁块内完成，杜绝并发重复启动（TOCTOU）；
- 评估进行中禁止再次评估与重置（409 守卫）；
- 异常分层处理：LLM 层失败 → 引擎内优雅降级（uncertain + 提示手评）；
  流程层失败 → 计错误数、保留重试；
- 标签库：AI 建议标签与教师标签统一入库计数，重置时按来源精确回收。
