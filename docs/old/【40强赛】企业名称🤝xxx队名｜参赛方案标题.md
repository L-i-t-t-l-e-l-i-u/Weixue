## 二、 方案成果展示【必须包含】

### **命题场景描述、问题描述及痛点说明**

**业务场景**：我们选择的是少儿思辨课堂（1–7 年级）的评估场景。思辨课以口头表达为主要产出，评价对象不是"标准答案"，而是学生如何提出主张、解释理由、使用证据、回应不同观点并反思自己的判断——一个 40 秒的课堂发言背后，是表达、推理、证据与视角的综合表现。

**四个结构性痛点**：

1. **年龄跨度大，同一套评分标准不公平**。1–2 年级孩子刚形成"理由可以支持观点"的意识，3–5 年级开始从单一确定答案走向多元观点，6–7 年级才逐步具备比较论据质量、回应反驳和反思判断的能力（Kuhn, 1999；Byrnes & Dunbar, 2014）。用同一把尺子衡量所有年龄段，要么苛责低年级，要么低估高年级。
2. **表层表达不等于思维质量**。儿童口语中的停顿、重复、错别字和句式不完整会严重干扰通用 AI 模型，但这些噪声不是"思辨能力弱"的证据；同时，原始表达又是教师回看学生真实水平的依据，不能丢。
3. **教师被高频机械劳动挤占时间**。逐字整理课堂转写、逐维度汇总评分、从零撰写评语、人工统计班级画像——这些重复工作占用了本应花在教学判断和个性化反馈上的时间。
4. **全自动 AI 批改绕过教师判断**。思辨评价天然包含教师根据课程目标与学生背景作出的主观校准，完全自动化会让评分失去可解释性与信任基础；研究也表明 AI 过度接管评价环节会削弱学生的深度学习。

**核心洞察**：问题不在于"如何让 AI 完全取代教师评分"，而在于如何让 AI 的结构化分析适配儿童认知发展，并帮助教师更高效、更可解释地完成最终判断——AI 准备，教师决定。

### 方案优势/创新点

**一句话亮点**：思辨题没有唯一答案——维学思辨星不替教师打分，而是把"不同年龄该评什么"和"教师怎么改"变成 AI 可执行、可回溯的评估流水线。

**原创与突破点（均已实现并实测，非规划）**：

- **统一五维评估 Rubric（企业对齐口径）**：以"立意、选材、结构、语言、视角"五个维度作为唯一核心评判标准，全年级共用同一套量表，每维度设 A+/A/A-/B+/B/B- 六级行为锚点；年龄适配通过"认知梯度合格线"表达（依据 Kuhn 认识论发展模型设定口径）：1–3 年级 ≥ B+（"敢说、说清楚"），4–6 年级及以上 ≥ A-（"观点明确、有依据、能换角度"）；高年级评分指导中设置反驳门槛：未考虑反面观点时"结构""视角"不高于 B+。加分项"有自己/有新意"不量化计分、命中综合评级升一档（A→A+），孩子不会因为没有展现超龄能力而被扣分；明确不评流利度、好词好句。
- **双层评估流水线（解耦设计）**：Layer 1 做语义无损文本清洗（去除口语填充词、修正错别字、规范标点），Layer 2 只依据清洗后的语义做五维评估，输出评分初稿 + 推理链 + 建议标签 + AI 置信度（certain_good / certain_weak / uncertain，不确定就明说不确定，绝不冒充已评）；原始文本始终保留供教师回溯，未来替换 ASR / OCR 不影响评估逻辑。
- **教师校准记忆（原创机制）**：教师每次覆盖 AI 评分，系统自动沉淀"AI 初评 → 教师终评 → 修改理由"，下次评估把最近 10 条校准记录以 few-shot 注入 prompt。实测（2026-08-15）：注入 5 条校准记录后，45 维一致率从 27% 提升到 40%，AI 评分偏高从 30 次降到 22 次（视角维度 56%→89%）。这是判断模式的传递，不是简单的"平均上调"。
- **教师决策门**：评分确认、标签选择、批注、评语定稿、发送给学生等每个主观评价节点都保留教师决策；课堂支持"快速评级"秒级确认，课后支持逐维修改，所有结果可解释、可回溯、可重置。
- **课堂现场伴学**：学生开麦口述，教师端实时看到"未发言→正在发言→已发言→处理中→已处理"状态流转；AI 给出追问建议，教师决定是否采用（最多三轮），把 AI 停在"建议层"，追问与判断权始终在教师。
- **双模式同构**：纯前端 demo 模式（GitHub Pages，零安装、打开即用）+ 真实完整模式（FastAPI + 真实 LLM/ASR），同一套页面与接口契约。
- **性能与成本实测**：45s 音频端到端转写 3.1s（RTF 0.07×），22 条样本平均逐字一致率 99.0%；批量评估 27 条零错误、26.4s/条；评语 5.4s/条；单节课成本约 ¥0.15；教师批改时间节省约 67%（详见"方案价值"）。

**Before → After**：

| 环节 | Before | After |
|---|---|---|
| 课堂转写 | 教师手动整理 30–60 分钟/节课，或转写后无人清洗 | 上传音频自动转写 + 口语噪声自动清洗，原文保留 |
| 维度评分 | 教师逐份人工评分约 3 分钟/条，口径靠记忆 | AI 五维初稿 26.4s/条批量生成（27/27 零错误），教师审阅 ≤1 分钟/条 |
| 评分校准 | 教师改分后无沉淀，下次 AI 依然"不听话" | 每次修改自动入库，成为后续评估的 few-shot 校准记忆（一致率 27%→40%） |
| 评语撰写 | 每生从零撰写 3–5 分钟 | 基于教师确认的评分/标签/批注 5.4s/条生成草稿，教师定稿后经飞书卡片发送 |
| 备课与报告 | 人工汇总薄弱维度与班级画像 | 按辩题自动聚合薄弱维度/低分学生，班级雷达图 + 家长报告一键生成 |

### 具体方案说明（突出AI能力）

**端到端流程**：

> 课堂音频 / 文本 → 可插拔 ASR 转写 → Layer 1 文本清洗 → Layer 2 统一五维评估（评分初稿 + 推理链 + 建议标签 + 置信度）→ 教师逐维确认（形成校准记忆）→ 评语草稿生成与发送 → 备课建议 → 班级 / 家长报告；评估数据双向同步到飞书多维表格，评语通过飞书机器人卡片推送，全程教师决策。

**核心功能模块（均已实现并走通）**：

1. **课堂表达接入**：教师上传课堂音频或粘贴转写文本；ASR 可插拔（演示 mock / 百炼 qwen3-asr-flash / OpenAI / DashScope），音频统一预处理为 16k 单声道 WAV；上传失败有客户端预检 + 后端全清理 + 粘贴文本人工通道兜底；切换真实模式自动隔离演示数据，互不污染。
2. **双层评估流水线**：同一套五维标准，按学生年级注入对应的评分指导与合格线口径，LLM 批量输出五维六级评分 + 推理链 + 建议标签 + 置信度；批量评估为后台任务，进度实时可见，失败可重试、防并发重入。
3. **教师审阅与校准**：逐维度改分、选标签、写批注；确认后自动写校准记录并注入后续评估；所有 AI 产物可逐条修改、可一键重置。
4. **评语生成与备课辅助**：评语基于教师已确认的评分/标签/批注批量生成（正反馈口径），可编辑后经飞书机器人卡片发送；备课页按辩题聚合薄弱维度与低分学生，讲评计划可导出 Markdown/JSON、同步飞书多维表格、推送机器人卡片。
5. **学情报告**：班级多维分析 + 维度雷达图 + Top 标签统计；点击任一学生可一键生成家长报告（能力画像 / 教师评语 / 下一步建议），教学线索给教师，成长叙事给家长。

**飞书 AI 能力应用（深度嵌在工作流中，不是外挂）**：

- **多维表格（数据层）**：5 张表（班级 / 辩题 / 学生 / 评估记录 / 备课计划），评估结果自动同步沉淀；支持双向同步——教师在多维表格中的修改可拉回本地库（8/13 真机往返验证通过）；字段所有权切分 + 防回环哈希 + 本地库唯一事实源，远端数据安全保留。
- **机器人（交互层）**：评语卡片"确认评分 / 去网页修改 / 发送给学生"，按钮回调经签名校验后真实回写系统；学生绑定飞书后评语可直发学生端（8/13 真实环境验证：小雨、豆豆、萌萌已送达）。
- **思辨星助教（对话层）**：教师可直接在飞书里对机器人发指令——"讲课计划""小雨的评语""查 大伟"等，白名单鉴权 + 知识库答疑。
- **Aily 智能体（AI 能力层）**：已连接多维表格读取真实评估数据，评委/教师可对数据直接提问；知识库以 IMPORT 模式导入（2026-08-15 定稿口径）。
- **长连接 ws_listener**：事件订阅与卡片回调统一分发，本地 NAT 环境无需公网回调地址，演示不受公网限制。

**工程可信度**：

- 后端 71 项自动化测试通过（15 个测试文件，子进程隔离、零网络零额度），覆盖 ASR 导入生命周期、批量评估全链路（防重入/降级/重试）、多维表格双向同步、飞书卡片回调、伴学对话、备课计划等；
- 演示数据往返链路 seed → 教师批改 → export → restore 逐字节一致，8/14 冻结前数据随时可恢复；
- 一键启动（`python start.py` 自动拉起 API + 飞书长连接）；配置安全审计通过（无真实密钥入库）。

**技术栈**：FastAPI + SQLAlchemy + SQLite ｜ React 18 + Vite + Zustand + Tailwind CSS ｜ 可插拔 ASR（qwen3-asr-flash / OpenAI / DashScope）｜ LLM（DeepSeek / DashScope / OpenAI 兼容）｜ 飞书开放平台（多维表格 / 机器人 / 长连接 / Aily）。

### 3.1 技术架构详解

**端到端架构（一图流）**：

课堂录音 / 文本 → 可插拔 ASR（qwen3-asr-flash / OpenAI / DashScope / mock）→ 双层评估流水线（Layer 1 文本清洗 → Layer 2 五维评估）→ SQLite 本地库（唯一事实源）⇄ 飞书多维表格（双向同步）→ 教师决策门（Web 前端 / 机器人卡片 / 多维表格）→ 评语 · 备课 · 报告；Aily 智能体连接多维表格与知识库，长连接 ws_listener 承载事件订阅与卡片回调。

**三个关键工程细节**：

- **双模式同构**：纯前端 demo（GitHub Pages，零安装打开即用）与完整模式（FastAPI + 真实 LLM/ASR）共用同一套页面与接口契约，切换仅取决于构建参数；

**可复现性**：`backend/benchmark.py all` 一键复现全部数字；原始报告与逐文件数据存档于 `docs/benchmarks/`（含转写准确率明细、官方账单核对、评语质量样例与清洗前后对照）。

### 3.3 团队协作：从"代码全乱"到 PR 工作流

我们 3 个人都是第一次正经用 git 协作，踩过最真实的坑：一开始不知道给 main 加分支保护，直接往 main 推，推之前也没看到队友的 PR，结果互相覆盖、代码全乱。后来给 main 加上锁（分支保护），所有人都走 PR 提交 + 交叉 review 合并，仓库才真正有序起来——从 8/2 到 8/16 一共合入 24 个 PR（编号 1–26），提交全部可追溯。

另外，团队自己用**飞书多维表格**当任务看板（任务 / 负责人 / 截止 / 状态 / 风险），dogfood 自家产品链路。

### 3.4 踩坑与取舍

- 妙记权限在比赛租户不可用（99991679，需用户身份授权）→ 自研可插拔 ASR 兜底并实测通过，妙记权限恢复后可无感接回、前端零改动；
- 明确不做全自动说话人分离：嘈杂课堂不可靠，交给教师确认反而更符合"AI 退后一步"的理念；
- 边界如实标注：校准 A/B 为模拟教师口径、转写样本为合成语音（儿童音色最低 91.4%）、耗时为本机墙钟——所有数字均可复现，不夸大。

### 3.5 未来迭代规划

- 更大规模真实教师验证（当前为团队演示教师口径 + 合成语音样本）；
- 课堂分段转写 UI（数据钩子与 transcribe_segments 已就绪，待前端接入）；
- WebSocket / SSE 实时状态通道，替换演示用的 BroadcastChannel；
- 多教师 / 多班级与跨校复用：评分口径可复制到答辩、演讲、写作评改等思辨表达类场景。

### 幕后故事和花絮 \(可选\)

为什么在这么多选题里选择了这个，其实是因为我真的作为老师跟这么大的孩子打过交道。

我一直在公益组织「太阳花」做志愿者，那里的孩子大多是随父母进城务工的随迁儿童。我带的是一门即兴戏剧课，第一课叫"即兴初体验"——带着孩子们玩"我是一棵树""镜像练习"这些游戏，课堂上有三条铁律：老师喊"123"，所有人喊"321"安静下来；谁犯了错，全班一起欢呼"Bongo"；一起编故事时，先接住别人的想法（Yes And），再往前走。规则很简单，但一开始，有的孩子怎么都不肯上台，有的孩子一开口就紧张得结巴。

可几节课下来，恰恰是那些最安静的孩子，冒出过最让我意外的点子。他们不是没有想法，是太少有人认真听他们把话说完——这句话，是我在太阳花最深的感受。一个孩子在课堂上说了四十秒，说话顺不顺，和心里有没有自己的理由，经常是两码事；可很多评价方式，太容易把"表达不流畅"当成"想不清楚"，随迁的孩子尤其吃亏。

所以拿到这个选题时，我几乎第一时间想到他们。维学思辨星的立场"AI 准备，教师决定"，说到底就是让 AI 把转写、清洗、评分初稿这些机械活干完，把时间留给老师真正去听孩子说话、追问孩子怎么想。如果这个产品能让更多"没被认真听过"的孩子被看见，那它就不只是一份参赛作品。
