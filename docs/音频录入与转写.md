## 1. 背景与目标

思辨课的作答来源有两种真实场景：

- **作业场景（场景 A）**：每个孩子一份独立录音，老师需要先确定学生身份（姓名+年级）再上传；
- **课堂场景（场景 B）**：老师提供整段课堂录音，需要切分成"话轮"并逐段指派给学生（半自动）。

本模块当前完成**场景 A 的完整闭环**（管理 + 录入 + 转写 + 进评估），并为场景 B 预留了全部数据与接口钩子。转写能力采用**可插拔设计**，与飞书妙记解耦——因为比赛租户的妙记 API 权限暂不可用（报 99991679，需用户身份授权），不能作为演示依赖。

## 2. 总体流程（老师视角）

```
管理 → 辩题管理（建题/改题） → 学生管理（添加学生） → 录音录入（选辩题×学生，上传或粘贴）
        ↓
转写写入作答（raw_text） → 智能评估（AI 评估） → 评语生成 → 备课/报告
```

页面结构：顶部 Tab 为「管理 → 智能评估 → 评语生成 → 备课辅助 → 学情报告 → 标签库」。"管理"是一个大页，内部三个**互不干扰**的子页。

## 3. 数据模型

```python
class AudioRecording(Base):
    # 一条原始录音（场景 A：一条录音 ↔ 一个作答；场景 B：一条录音 → 多个作答）
    id, course_id, topic_id, file_path, duration_ms, created_at

class StudentResponse(Base):
    # 新增字段
    source = "manual" | "audio" | "asr"     # 作答来源
    audio_recording_id = FK(AudioRecording) # 关联录音
    segment_start_ms, segment_end_ms        # 场景 B 分段（暂未使用）
```

**关键关系**：`StudentResponse(student_id, topic_id)` 本身就是学生 ↔ 辩题的关联表——"辩题里有哪些学生""学生在哪些辩题里"都是对它的直接查询，前端 store 已加载全部作答，纯前端即可完成交叉展示与移除。

## 4. 转写抽象层（backend/asr.py）

可插拔设计，`ASR_PROVIDER` 环境变量切换；运行期也可通过前端「录音录入 → 转写模式」按钮或 `GET/POST /api/settings/asr` 切换并持久化（真实模式会自动清除演示种子数据，切回 mock 且库为空时自动补种）：

| 提供商 | 配置 | 说明 |
|--------|------|------|
| `mock` | 默认 | 返回内置演示转写文本，离线可用，比赛演示保底 |
| `qwen_asr` | `ASR_PROVIDER=qwen_asr` | **推荐**。百炼 `qwen3-asr-flash` 走 OpenAI 兼容 chat/completions，音频 base64 内嵌直传（无需公网 URL），单文件建议 ≤7MB；LLM 为百炼时复用 `LLM_API_KEY`，否则单独设 `ASR_API_KEY`。已验证：端点/模型/key 可用（空音频探测返回业务错误而非 404/鉴权错误），DashScope compatible-mode 无 `/audio/transcriptions` 端点故不走 whisper 路线 |
| `openai` | `ASR_PROVIDER=openai` | OpenAI 兼容 `/audio/transcriptions`（whisper），需音频端点与 key |
| `dashscope` | `ASR_PROVIDER=dashscope` | 百炼 paraformer SDK（`Recognition(...).call(本地文件)`），需 `pip install dashscope` |

接口：

- `transcribe(file_path) -> str`：转写整段文本（场景 A 使用）；
- `transcribe_segments(file_path) -> [{start_ms, end_ms, text}]`：带时间戳分段（场景 B 钩子，mock 返回假分段便于离线开发）。

`ASR_API_KEY` 留空时复用 `LLM_API_KEY`。

## 5. 音频预处理工具（backend/audio_utils.py）

课堂录音格式五花八门（m4a/webm/ogg/mp3/手机录像 mov…），而 qwen_asr 与 paraformer 最稳的输入是 **16 kHz 单声道 PCM WAV**。`audio_utils.py` 提供统一入口：

```bash
python audio_utils.py convert 输入文件 [输出.wav]   # 转 16k 单声道 WAV（默认输出 同名.16k.wav）
python audio_utils.py sample [输出.wav]             # 生成 30–60 秒示例课堂音频
python audio_utils.py info 输入文件                 # 查看时长/大小
```

要点：

- 转码走 ffmpeg（`-vn -ac 1 -ar 16000 -c:a pcm_s16le`），自动丢弃视频轨；
- **缺 ffmpeg 不抛堆栈**：按平台给出安装提示（macOS `brew install ffmpeg` / Ubuntu `apt-get` / Windows `winget`）后退出；
- `sample` 子命令在 macOS 上用系统中文语音（Tingting）合成约 45 秒课堂发言示例，无 ffmpeg 也能产出；ffmpeg 可用时会再过一遍 `to_wav16k` 归一化，与真实录音走完全相同的管线；
- 仓库已附带示例音频 `backend/data/sample_class_audio.wav`（45 秒，16k 单声道，可直接用于 qwen_asr 实测）；
- 已验证路径：m4a→16k WAV 转码成功（45.05s）、缺 ffmpeg 提示正确退出、坏输入给出清晰 ffmpeg 报错。

> 演示/测试环境若不便安装系统 ffmpeg，可 `pip install imageio-ffmpeg` 后把其自带的
> arm64/x86_64 二进制软链为 `ffmpeg` 放进 PATH，效果等同（本机验证即用它）。

## 6. 后端接口清单

| 方法 | 路径 | 作用 |
|------|------|------|
| POST | `/api/courses` | 新建班级（从零开始） |
| POST | `/api/courses/{cid}/topics` | 新建辩题 |
| PUT/DELETE | `/api/topics/{tid}` | 修改/删除辩题（删除级联作答） |
| POST | `/api/courses/{cid}/students` | 单个添加学生 |
| POST | `/api/courses/{cid}/students/batch` | 批量添加学生（重名跳过） |
| PUT/DELETE | `/api/students/{sid}` | 修改/删除学生（删除级联作答） |
| POST | `/api/courses/{cid}/audio/import` | 上传音频 → 转写 → 写入作答（重置旧评估） |
| POST | `/api/courses/{cid}/responses/text` | 粘贴转写文本（手动录入） |
| DELETE | `/api/responses/{rid}` | 删除单个作答（级联清理校准记录与录音） |

所有接口均有纯前端 demo 模式（`demoClient.js`）对应实现，GitHub Pages 可完整演示。

## 7. 前端结构

```
src/pages/
├── ManagementPage.jsx      # 管理大页（三个子页切换）
├── TopicsManager.jsx       # 辩题管理：CRUD + 排序 + 查看学生（含移除作答）
├── StudentsManager.jsx     # 学生管理：单个/批量添加 + 编辑/删除 + 查看辩题（含移除作答）
├── RecordingsManager.jsx   # 录音录入：选辩题×学生，上传音频或粘贴文本
├── GradingPage.jsx         # 智能评估：只显示有作答的学生（空班级显示空状态）
└── ...
```

批量添加学生格式：每行 `姓名,年级`，兼容 `小雨,1年级` / `豆豆 2年级` 等写法。

**上传兜底（RecordingsManager）**：

- 客户端预检：扩展名白名单（mp3/wav/m4a/aac/ogg/amr/wma/flac/webm/mp4）、总大小 ≤20MB、
  qwen_asr 模式下 >7MB 提前提醒；
- 失败分级提示：400（格式/参数）/ 413（过大）/ 502（转写服务异常）/ 500·503（后端/依赖不可用）/
  超时 / 断网，各自给出可操作的文案，且都引导老师改用右侧「粘贴转写文本」兜底——
  任何一类失败都不会白屏或卡死录入流程；
- 转写模式切到真实 provider 但未就绪（缺 key 等）时，上传按钮禁用并悬浮提示原因；
- 后端对失败上传做全清理：不留临时文件、不留 AudioRecording/作答残行。
